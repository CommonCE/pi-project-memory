# 0001 — 项目身份先于记忆检索

状态：已实现于 0.1.0；项目边界/启用规则已被 [0002 — 强制 .pi-root](0002-require-pi-root.md) 覆盖；第一版不学习的范围由 [0003 — 学习、审核与交接](0003-learning-review-handoff-init.md) 扩展。以下保留第一版历史决策。

## 背景

用户已有 pi-memctx 与项目相关的 pi 配置，希望项目归属成为插件原生能力，而不是依赖环境变量、启动脚本或提示词切换。实现基于本机 pi 扩展/包文档及已安装的 pi-memctx 0.13.1 的存储形式，没有修改旧插件或自动迁移旧映射。

## 决策

1. 当前真实 cwd 的最近项目边界决定项目身份；默认 id 使用目录名和路径 hash。
2. 独立中央注册表保存根目录与 pack 的关系；显式项目 JSON 可以固定 id 和 packPath。
3. 提示词不能切换项目。跨项目切换仅通过用户命令；模型保存工具没有项目参数。
4. 保留六类 Markdown 目录和 wikilinks。每次保存新建不可覆盖笔记，不自动合并。
5. 默认本地关键词/BM25检索，不调用额外模型；注入内容只供参考，不发布硬性工具预算。
6. 第一版不自动归档对话，避免未经核实事实和敏感信息被批量保存。
7. 原位接入旧 pack 只写新注册表。旧映射的格式未完整核对，不推测性迁移。

## 代价与后续

- 项目移动/重命名会改变默认 id；需要固定 id 配置。
- 同名笔记可能重复，需要人工整理；缺少自动学习、qmd 和 review queue。
- 本机扩展入口及工具通过 host Jiti/TypeBox 验证，但还需实际 TUI 会话验收。
- 后续可增加独立测试过的旧映射导入器、只读接入模式和显式 review queue；不应削弱项目边界。

## 验证

`npm run check` 与指定 `PI_TEST_HOST_PACKAGE` 的 `npm test`；全部 16 项测试通过。测试使用临时目录，不接触真实用户记忆，也不调用模型或提交计算任务。
