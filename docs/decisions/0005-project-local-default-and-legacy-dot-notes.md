# 0005 — 项目内默认 pack 与旧 .md 笔记兼容

## 状态

0.2.1 已实现，本地回归通过。

## 背景

显式 setup 原本使用项目内目录，但 resolveProject 对尚未配置/注册的标记项目仍回退到中央 vault。已有项目直接启动或低层 init 因此不会默认使用项目自身的旧 pack。

实际旧 writer 还可能把非拉丁标题保存为恰好 `.md` 的文件；全量隐藏文件过滤会漏掉这种有完整 frontmatter 的有效旧笔记。

## 决策

- 未绑定项目默认路径为 `<root>/pi-memory/packs/<slug(basename(root))>`。
- 显式 packPath、已有注册绑定和手动目标选择的优先级不变，不自动迁移旧中央 pack。
- 注册元数据仍在 vault/projects，正文默认随项目存放。
- 保留原始旧文件，不做改名或原位格式转换。
- 仅为名为 `.md` 的普通文件开例外：必须有受支持的 type 和非空 title frontmatter；继续实施敏感内容、大小、扫描上限和后代符号链接校验。
- 其他隐藏文件和隐藏目录仍不读取。

## 验证

- 新增项目内默认路径/低层 init 与旧 `.md` 兼容测试。
- 显式构造旧中央注册绑定，验证升级不会重绑定。
- 完整宿主测试 74/74 通过。
- 在 WSL DrvFS/9p 文件系统上执行并发和新增回归测试，6/6 通过。

## 测试隔离修复

TMPDIR 位于真实标记项目下时，并发夹具的 setup 会合法继承父级标记，而不是得到独立项目。夹具现在先在新建临时 root 中显式写 `.pi-root`，并断言有效 root 和 pack 路径；不允许落入父项目。原有 Markdown 文件集合和 SHA-256 复核不变；测试隔离不以修改原文件为代价。

## 文件系统边界

仅验证同一 WSL 挂载内的硬链接、锁和崩溃恢复。DrvFS 在未启用 metadata 时可能显示 777，不能宣称 Unix 0600 权限生效；敏感内容须依赖正确的 Windows ACL。OneDrive 跨设备同步、分布式锁与断电耐久性没有得到验证，禁止同时在多台机器写同一 pack。
