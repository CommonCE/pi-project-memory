# 0004 — 完整写入后原子发布新记忆文件

状态：已实现于 0.2.0 测试补强阶段。

## 证据

多进程测试让写入者在候选 JSON 写到一半时暂停，另一个进程调用 listCandidates。原先 exclusive() 直接用 wx 写最终路径，读者可以看见半文件：

```text
SyntaxError: Unterminated string in JSON at position 197 (line 7 column 10)
```

队列锁只保护写入，不阻止只读的列表/搜索/注册表读取，因此写锁本身不足以避免这个窗口。

## 决策

所有 exclusive() 新文件写入改为：

1. 同目录创建随机、固定短文件名的隐藏临时文件，open wx，0600。
2. 写完 UTF-8 内容并关闭文件描述符。
3. linkSync(temp, final) 原子发布；目标存在则 EEXIST，不替换任何文件。
4. finally 删除本次创建的临时文件；遇到实际进程终止可能留下未发布隐藏文件。

临时文件名不包含原 basename，避免为长 Unicode 名称增加字节导致超过文件系统组件长度。注册表、manifest、候选、审核决定、笔记和显式初始化都复用此 helper。

## 边界

需要文件系统支持同目录 hard link；不支持时拒绝并报告错误，不采用会覆盖目标的 rename fallback。此方案保证完整文件的可见性和非覆盖，不承诺突然断电后的数据耐久性（没有引入 fsync 协议）。遗留锁仍须确认进程已退出后人工处理。

## 验证

- 暂停在半写状态时，读者只能看到原先的空队列，发布后看到完整记录。
- 8 进程同候选入队：仅一条候选，其余显式 busy 或去重。
- 8 进程批准：仅一条笔记与一个不可变决定。
- 真正退出子进程，模拟笔记写完、决定尚未发布：检查遗留锁，确认进程退出并显式清锁后重试；笔记字节保持不变，不重复生成。

全部操作仅在测试新建的临时目录进行，不涉及用户真实记忆或昂贵计算结果。
