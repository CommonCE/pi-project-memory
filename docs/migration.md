# 格式与升级边界

当前实现仅加载 `index.ts`，存储为 `.pi-memory-local/`，格式标识为 `pi-project-memory/current-notes-1`。这次架构收缩调整了 CLI、工具和内部格式，包版本按要求没有修改。

原 `v2.ts`、v1/v2 存储与配置加载器已删除。旧 `.pi/project-memory.json`、`.pi-memory/`、`.notes/`、`pi-memory/` 不被读取、覆盖、删除或自动迁移。启动发现这些常见路径时给出说明；不扫描它们的内容或项目外注册表。仅有旧数据时返回 `legacy-format`，须显式 `/memory-init` 或 CLI `init` 才会创建隔离的新存储。两种目录可以同时存在，当前插件只读新目录。

不要把旧目录改名为 `.pi-memory-local`，也不要将旧规范记录或投影页复制成新格式假装兼容。新路径已存在但格式未知、缺少清单或格式不同，会明确拒绝接管。旧格式迁移工具不在这次范围内；如需迁移，应另行确定输入、人工筛选和输出位置，不覆盖原件。

用户若曾显式加载 `v2.ts`，需将加载路径改为 `index.ts`；包默认入口仍为 `index.ts`。原候选、审核、实体、卡片、文件夹作用域、consolidation、恢复投影和自动提炼接口全部退出，不保留兼容分支。原 `pi-memory-init` 可执行文件退出；使用 `pi-project-memory init` 或 Pi 的 `/memory-init`。

新笔记默认 `unverified`，只有显式设为 `active` 才能进入默认上下文。纠正使用同一 ID 与当前文件哈希；失效改为 `inactive`。历史修订不自动保存，新格式中也没有历史事件参与默认上下文。旧会话里的聊天、工具结果及压缩摘要不会被此插件追溯擦除。

本次删除的是仓库内被替代的实现、专属测试及重复维护文档，不触碰项目真实记忆包、运行输出、检查点或科研产物。对于旧代码中已修复的行为，保留到新契约中：撤回默认排除、过期修订冲突、来源与不确定性保留、完整笔记放入或省略，以及当前任务优先。
