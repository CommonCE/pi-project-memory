## 1. 只解决一个使用问题

用户在计算目录工作后，新开会话说“继续”，插件能简短说明当前任务、已知结果及限制、未完成事项；用户可手动查看记忆并显式纠正错误。

已有能力保留：显式保存/修订、搜索、工作记录、state、候选审核、首轮简报、目录页和 compaction handoff。M7 不重建这些系统。

## 2. T1：手动简报

### 接口与实现顺序

- CLI 新增 `v2 brief [--folder <rel>]`，输出结构化 JSON。
- Pi 新增 `/memory brief`，先只查看当前目录；与 CLI 调用同一生成器，不另写摘要逻辑。
- 分两小步实施：先共享只读入口和 CLI，再接 Pi 命令。Pi 接入前按规则核对适用宿主文档，不引入新事件/API。
- 既有 `context`、`folder show` 和搜索契约不变；`folder show` 是派生页，不代替实时简报。

### 最小返回与边界

共享只读入口建议返回 `{content, chars, folder}`；未启用时返回空 content、chars=0、folder=null，不创建项目标记或配置。

- 默认当前目录；显式 folder 经现有 scope 路径校验，包含可继承祖先，不默认包含兄弟。
- 支持安全的历史缺失目录；无记录明确说明，不伪造最近运行。
- content 最多 1200 UTF-16 code units；工作上下文仍最多 12000，不提高预算。
- 内容与自动首轮简报复用同一生成器，保留来源、未知/失败限制和非执行授权提示。
- 手动查看不写事件、不触发提炼、不改变首轮注入资格、不隐式 rebuild。
- 返回完整 JSON；内容内若有预算省略，沿用现有显式省略提示。

### 验收

失败测试覆盖当前/显式目录、继承与兄弟隔离、历史目录、空目录、禁用状态、参数拒绝、1200 字符上限及零写入。与既有首轮生成结果对照时固定时间，避免“距上次活动秒数”的抖动。

## 当前进度与最小用法

已实现 `readBriefV2(project, {folder?})`、CLI `v2 brief [--folder <rel>]` 和 Pi `/memory brief`，返回 `{content, chars, folder}`。

```text
v2 brief                         # 当前目录的实时简报
v2 brief --folder calc/opt        # 显式目录，允许安全的历史缺失目录
```

以上为现有 CLI 的 v2 子命令部分，不是独立的 v2 可执行文件。完整命令例如 `node "$PACKAGE_ROOT/bin/pi-project-memory.mjs" v2 brief --folder calc/opt`。

最小续接用法（仅在用户选择的新试验项目中，不在本仓库初始化）：

1. 显式加载 `v2.ts`，不要同时加载默认 v1；步骤见 [M2 使用说明](m2-usage.md#1-如何启用)。没有标记/配置不会自动初始化。
2. 显式要求 `project_memory_save` 保存相关体系、方法、运行与结果；附软件版本、单位、已知来源和失败/未知限制。工具成功写入不代表科学验证。
3. 在相应目录使用 `/memory brief` 查看实时简报，`/memory search <query>` 找回知识、`/memory get <uuid>` 查看完整记录。手动 brief 仅当前目录，不接收参数；CLI 可显式指定历史目录。
4. 新会话在同一目录说“继续”，首轮带目录简报；换项目/目录及切回会重新带简报。简报不授权执行未完成步骤或重跑计算。
5. 显式纠正时先读取当前记录，再以同一 ID、`expectedRevision` 和完整 entry 修订（保留 card、固定来源及单位）；旧修订不改写。CLI `v2 get <uuid> <revision>` 可核对历史，另见 [M1 修订契约](m1-usage.md#cli-契约)。不同实际重跑应新建 run，而不是把旧失败来源改成成功。
