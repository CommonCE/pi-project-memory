# M4 开发目标：计算化学记忆生成与续接

## 目标与完成标准

M4 的主目标是：从计算化学工作过程自动选出有用、可追溯且不失真的记忆，供下一会话继续工作。
矩阵覆盖、软件单测及保存条数是诊断指标，不是该目标已达成的证据。
默认入口仍是旧版 `index.ts`；新版须显式加载 `v2.ts`，不同时加载，不在本阶段更改安装默认值。

应按来源与适用范围恢复以下内容；不存在的字段明确保持未知，不补默认值：
- 体系、方法、软件/版本、电荷/自旋、单位及其证据；只保留材料中实际提供的信息。
- 输入/输出位置、运行身份、执行/终止/收敛/科学有效性；输入生成不等于执行，最后迭代能量不等于有效结果。
- 错误与失败阶段、诊断假设、旧新参数、是否采纳、是否重跑及待验证限制。
- 用户目标与约定下一步；助手建议不是用户承诺，“继续”不授权提交或运行计算。
- 方法修订、独立运行和同名体系不串线；软件任务不强加计算化学字段。

## 开发优先级

1. 先建立一个纵向样例：失败计算与未执行恢复建议，经实际提炼 API → pending → 人工批准 → 知识存储 → 新进程召回。
   金标同时检查候选、知识命中与召回上下文；不向工作状态复制答案来掩盖提炼遗漏。
2. 根据失败定位生产瓶颈：来源选择、必要限定保留、实体/修订关联、预算或召回；每次只修一个可复现问题。
3. 扩展准备未运行、修改方法后独立重跑、同名体系与多运行等代表场景。
4. 验证实际离线 Pi 会话切换；新 Node 进程只能证明持久化恢复，不是宿主会话验证。
5. 经单独授权后，用脱敏代表材料和真实模型自动选择候选；保留模型/配置、usage、材料摘要及独立人工逐事实审阅。

## 必须分开的证据层

| 层 | 判定范围 |
|---|---|
| 固定响应纵向契约 | 证明生成、审核、存储、恢复链路的保真与负对照有效；不能证明模型会选对来源 |
| 实际模型选择 | 评估重要事实遗漏、无依据提升、错误关联及有用性；提示词文字测试不能代替该层 |
| 实际宿主续接 | 检查新的 Pi 会话仅问“继续”时能恢复什么；不能用新 Node 进程冒充 |
| 科学审阅 | 检查记忆忠于证据及限制，不把批准/软件通过当成化学结论成立 |

M4 完成必须同时报告这些层的已通过、失败、未运行/未授权范围。
固定材料关键事实应全部恢复，禁止性提升与错误归属为零；任何未测层不得从其他层外推。
若真实模型或宿主层尚未验证，只能交付“基础设施/离线契约完成”，不能宣布实际生成质量已改善。
现有 `eval/m4-matrix.mjs` 继续作为回归缺口清单，不再作为唯一开发优先级或效果指标。

## 当前实现范围

首个纵向 runner 为 `eval/m4-chemistry-generation.mjs`，使用固定响应适配器，不调用远程模型或科学软件。
新增 `eval/m4-chemistry-scenarios.mjs` 覆盖准备未运行（49 项）及方法修改后独立重跑（90 项，含两项实体背景可区分性检查）。
前者保留输入位置、未执行/无能量及权限限制；后者保留旧失败与新报告、方法变更、单位/有效性限制，并按独立运行身份检索和恢复。
运行身份锚点和活动身份由夹具显式提供，不代表模型已能自行识别实体；没有实际执行重跑。
重跑样例现使用共享体系 + 当前 run 的活动状态，而非仅 run ID；这曾造成旧/新能量互串，原 88 项中有 4 项失败。
已修复知识上下文：优先选定 run，排除明确归属其他 run 的知识；保留共享背景与显式多 run 选择，数值以 result.runId、自身 run 以记录 id 为准。显式搜索仍宽检索，工作历史不重写。
独立回归还覆盖同名体系、前八项被旧运行挤占及带错误附加引用的数值结果；不代表自然语言实体识别或任意材料召回已验证。
提炼端曾只提供同名实体的 UUID/类型/标题/修订号，固定适配器因预先知道 ID 掩盖了信息缺口。改为仅消费实体背景后，90 项中 21 项失败。
现在向显式选定 current 实体提供最多 800 UTF-16 code units 的脱敏已有内容/run 元数据，标记 background-only；身份和原任务背景先占预算，描述可省略且绝不能 grounding。
纵向消费者据背景区分 run-A/B 后恢复 90/90；这只证明信息可用和背景隔离，不证明真实模型选择准确。
误导肯定标题、合法但错误或缺失的 run 引用均能通过 grounding/批准，但必须被质量门槛拒绝；缺失关联不能由上下文筛选自动补全。
两个 runner 均独立于原 49 案例矩阵入口；未接入统一验收门槛，不据此提升 M4 完成状态。
首个样例已发现并修复：窄查询只返回匹配行，会丢失同条提炼记录的未采纳/未重跑建议。
`model-extraction` 记录现在对完整正文做有界摘录，不先按关键词或七行筛掉互补来源；其他来源保留原行为。
准备场景又发现短正文加多来源/运行元数据超过原单项 1600 的问题：完整摘录 929，JSON 1719（UTF-16 code units）。
模型提炼记录的上下文单项 JSON 上限现为 2048，其他来源仍为 1600；检索 excerpt 1400、最多四项和总上下文预算保持不变。
这是呈现预算调整，不迁移存储或升级科学状态；较大单项可能挤占后续项，总预算不足时仍截断/明确省略，不保证任意长材料的全部中部事实。
提炼提示补充计算化学来源选择优先级；这是指导性变化，不是对真实模型有效性的验证或安全边界。
所有项目及 `.pi-root` 仅在新建临时沙箱中创建并清理；不扫描真实计算目录，不修改用户设置。
真实模型、真实数据和科学计算/提交仍须分别授权；本次目标更新不扩大这些权限。

## 有界真实模型小样本与恢复建议关联

经独立授权，使用 `openai / gpt-6.1-sol`、`openai-responses`、推理强度 `low`，完成 5 次固定合成材料选择；无工具、不发布真实记忆。
首批一次请求前失败也计入额度；随后按剩余 5 次、单次 30 秒、整批 150 秒、串行且不重试执行，不再以 token 数量作为硬门槛。5 次均 HTTP 200，总耗时 42.328 秒，最长单次 10.133 秒；授权额度已用完。
这是低层 SDK 选择测试，不是 Pi 会话续接或科学计算，也不是独立人工科学审阅。原始记录仅在本次会话的新临时目录，不把本地临时路径作为可移植夹具。

- 准备未运行 0/1：漏选助手建议中的“不是用户承诺/执行许可”限定，但仍保留用户原有的禁止执行约束。
- 方法修改后独立重跑 2/2：预定事实与运行关联均保留。
- 同名失败运行 0/2：恢复建议两次均已选出，但没有关联到原 run-A；不是文本遗漏。
- 原始引文覆盖 29/30，按运行作用域覆盖 27/30；严格案例门槛 2/5。样本很小，不能外推总体准确率或据此宣布 M4 完成。

下一步据此补充提炼提示：保留未采纳/未运行建议及权限限定；运行专属建议同时 grounding 建议与显式原运行证据，关联原运行而非猜测的新运行。身份含糊时仍不关联，不在解析/存储层自动补 run ID，不提升运行状态或验证级别。
新增 `eval/m4-chemistry-followup.mjs` 重建合成响应形态：独立主记录 + 后续建议，经实际提炼 API、pending/批准、按 run 查询与新 Node 进程恢复。准备正例 55 项、原失败运行正例 46 项；另有漏选、未关联及错误关联负例。
未关联负例必须保留候选、发布和宽查询中的原建议，同时不能通过运行限定的金标；这将来源保留与任务归属分开诊断。关联含糊的单测保留空引用，不用错误关联换取覆盖率。
该 runner 独立于旧 49 案例统一矩阵；固定响应通过只证明离线契约有效。提示增加 185 UTF-16 code units，会占用原有输入预算，未提高预算上限；最小 2048 预算仍有回归覆盖。
提示改动后的真实模型效果、实际 Pi 续接及独立科学审阅仍未验证；没有剩余调用额度，追加模型测试须重新授权。
