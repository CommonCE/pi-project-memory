# 长期记忆总体架构与项目盘点

状态：按本轮架构讨论整理的目标架构。本文统一设计方向，不宣称新增能力已实现，不改变既有 CLI、存储、schema 或权限契约。
进度来自阶段文档与测试报告的定点核对，未审计全部代码、未重新执行历史测试。
开发优先级见 [路线图](roadmap-v2.md)，当前实施任务见 [M7 最小计划](m7-plan.md)。

## 1. 定位与设计原则

面向科研计算、软件开发和集群操作等长期项目，帮助用户“记住—找回—继续—纠正”。长期记忆不是聊天压缩仓库，而是经过筛选、带适用条件、来源和修订关系的项目知识。

优先级：作用域正确 > 不歪曲证据 > 当前上下文质量 > 可追溯与可维护 > 自动化程度。

- 项目优先：当前项目是默认读写边界，不自动扫描其他项目。
- 保守准入：允许零候选；保存过的信息不自动成为可信事实。
- 上下文是视图：记忆保存量与每轮注入量解耦。
- 当前代码、文件和用户授权优先于历史记忆；记忆不是新的指令权限层。
- 更新保留依据，区分纠错、环境演变和未解决冲突。
- 先复用既有存储、审核、隔离与恢复保护，不重建第二套系统。

DeepSeek Super Agent 相关术语仅作为本轮讨论的参考线索；未取得可核实的一手资料，不把本文方案归因为其已公开实现。

## 2. 总体结构：区域与维度分开

```text
当前任务 / 会话 / 文件与工具观察
                  ↓ 有界采集
        Working Memory ──→ 交接视图
                  ↓ 有意义变化 / 显式请求
               候选区
                  ↓ 去重、核验、接纳
             Project Memory
                  ↓ 显式跨项目适用性审查（后期）
              Global Memory

Archive：历史版本与被替代判断
Evidence：原始来源、关键片段与验证依据
二者贯穿上述过程，不是统一的最后一层。

召回：任务 → 作用域 → 主题/对象与检索 → 状态/关系检查 → 必要证据
                                      ↓
                             有预算的上下文视图
```

Working/长期描述工作阶段；Project/Global 描述适用范围；Archive/Evidence 描述历史与依据。成熟的项目知识不因此自动成为全局知识。

| 区域 | 职责 | 现有基础与差距 |
|---|---|---|
| Working Memory | 当前目标、观察、假设、阻塞、下一步与会话交接 | M2 journal/state/overview、compaction handoff；M5 首轮简报；M7 手动简报部分完成 |
| Project Memory | 项目事实、决策、经验、流程及重要未决问题 | M1 修订存储、M3 候选审核/实体检索、M5 scope、M6 卡片；治理还需统一 |
| Global Memory | 少量长期偏好、通用约定、跨项目流程入口 | 尚非当前能力；不借此开放跨项目自动检索 |
| Archive | 历史判断、旧修订、被替代记录 | 已有修订与固定来源基础；不等于完整归档产品 |
| Evidence | 支持结论的原始会话/文件/工具观察及身份 | 已有 grounding、来源修订和摘录基础；不能宣称完整原始来源已持久保留 |
| 候选区 | 隔离未接纳信息 | M3 已有；未批准内容不进入正式知识召回 |

项目根下的目录 scope 是 Project Memory 内部适用范围，不是独立记忆层。祖先继承与兄弟隔离继续沿用；项目、目录、实体、来源运行不能互相替代。

## 3. Inline & Spill：最小自足结论与可发现详情

Inline 优先：当前目标与禁止事项、影响本次行动的已接受决策、任务位置、必要风险、少量长期偏好。
Spill 优先：完整日志、排错过程、历史方案比较、流程全文、旧会话和历史版本。

Spill 入口说明“是什么、适用于什么、何时读取、来源在哪里”，而不是仅给路径。
结论不能与决定其含义的条件拆开：软件版本、体系/方法、单位、失败与未知限制必须随结论保留。

现有简报 1200、工作上下文 12000 UTF-16 code units 的预算不因新架构提高；必要省略显式展示。长内容按需读取，不新增第二套摘要生成器。

## 4. 召回：有界混合，而非强制图遍历

1. 确定项目、目录及当前任务；显式对象或路径可直接定位。
2. 用主题、实体与全文检索发现候选；按实际需求再增加语义候选。
3. 检查有效修订、适用范围、冲突和证据状态。
4. 只沿必要关系展开，并在必要时读取原始依据。
5. 形成有预算的工作视图；没有足够依据时明确报告缺口。

| 机制 | 职责 | 非职责 |
|---|---|---|
| 结构化关系 | 适用范围、关联对象、替代与证据依赖 | 根据关系存在认证事实 |
| 全文搜索 | 名称、路径、错误码、版本与关键字精确命中 | 单独解决跨措辞匹配 |
| Embedding（后期） | 模糊症状、同义表达、跨措辞发现候选 | 判断授权、适用性、有效性或真实性 |

Chain of Recall 采用有界查找，不追求遍历所有知识。后续任务需要明确候选数、关系跳数、证据展开与停止条件，但本轮不制定新接口或参数。M3/M5 的实体、全文与祖先链是基础，不等于通用关系图已实现。

## 5. 类型与状态：语义分类不是验证等级

以下为目标语义，不是本轮新增存储枚举：

| 类型 | 最低语义要求 |
|---|---|
| fact | 陈述、适用范围、来源；区分用户陈述、文件记载与实际验证 |
| decision | 选择、理由、约束与被放弃方案；不是普遍最优解 |
| preference | 主体、场景与长期性依据；一次性要求不自动推广 |
| procedure | 前置条件、步骤、成功判据、失败出口 |
| problem/solution | 症状、环境、原因判断、措施、验证；区分绕过与根治 |
| pending | 待核实/待完成事项、重新检查条件；不伪装成既成事实 |

类型、审核接纳、证据性质、当前适用性、运行有效性彼此独立。pending 优先留在 Working 或现有任务系统；只有跨会话影响判断的事项才长期保留，解决后退出活跃视图。

科研 systems/methods/runs/results/diagnostics 卡片表达领域对象，不取代上述知识语义；普通软件开发不必承担科学字段。

## 6. 生命周期与 consolidation

### 6.1 产生与接纳

产生 → 候选 → 去重与范围核对 → 证据核验 → 接纳或拒绝 → 按需召回。

优先触发：明确保存请求、已确认决策、经验证的问题解决、结果推翻旧认识、稳定流程形成。
准入检查：是否改变未来行动、是否跨会话有价值、是否能从权威来源廉价恢复、是否有明确条件和依据。

现有 M3 默认 review、每用户范围最多一次有界提炼调用是当前契约，不因本方案悄然改变。未来将“每回合提取”调整为变化/里程碑触发前，需要独立设计和成本、漏记评估；显式保存始终保留。

### 6.2 两种整理

- 轻量交接：记录目标、实际进度、工作入口、未决事项和下一步；不提升知识验证等级。
- 长期 consolidation：在有意义的里程碑对新增信息做去重、冲突比较、来源核对和候选接纳；允许零产出。

会话结束是整理机会，不是唯一触发器；异常退出不能导致关键工作只存在于结束钩子中。不新增“每轮生成长期摘要”的后台流程。

### 6.3 更新、失效与归档

- 补充：新增解释或证据，结论未变。
- 纠错：原判断错误，明确更正与依据。
- 演变：原判断曾适用，环境、方法或决策改变。
- 冲突：同范围下的说法不兼容，尚未裁决。

先检查范围与版本，避免把不同条件下都成立的说法误判为冲突。不以新近写入自动取胜，不因审核批准提高科学有效性。沿用既有修订机制，不承诺已有专门冲突界面。

不设统一 TTL。环境知识随版本/配置变化复核，历史决策保留解释价值，pending 有关闭或复核条件。过时表示不能直接依赖，不等于删除。隐私、用户删除要求与保留策略需要独立处理；不可变历史不应成为永久保留敏感信息的借口。

## 7. 证据链与失真控制

目标链：记忆结论 → 具体支持片段/观察 → 原始来源及其身份或版本。

- 用户选择可由明确会话确认支持；测试通过和科学结果必须有相应执行/验证依据。
- 定位到路径不等于永久保留证据；文件可能变化、输出可能消失。
- 高价值结论优先保留最小必要证据片段与来源身份；大型科学产物原则上保留定位，不复制进记忆。
- 原始来源不可访问时明确降级可核验性，不伪造定位或宣称已检查。
- 同一来源的多次转述不是多份独立证据；consolidation 尽量回到原始依据。
- 不保存 thinking、凭据、完整敏感日志；不默认复制全部会话或工具输出。

现有固定来源修订保护继续保留。是否增加来源身份校验、证据失效提示或证据保留机制，要先列出现有覆盖与真实缺口，不能另建重复存储。

## 8. Project / Global 与 Skill 边界

新知识默认属于产生它的项目。跨项目提升是单独审查，不是成熟度自动升级。

Global 可容纳长期语言/交付偏好、明确通用约定、可复用流程入口；某项目的方法选择、某集群当前路径、单次修复命令不能直接推广。
多项目共享的集群/软件环境先用适用范围组织，不立即增加新的顶层记忆区。

AGENTS.md、项目文档和 Skill 继续承担其权威职责；记忆保存入口及必要背景，不维护一套会漂移的规则副本。历史提交或计算授权不能成为本次执行授权。

长期提升链：problem/solution 案例 → 多案例比较 → procedure → 经审查和验证的 Skill 提案。
频繁出现仅说明值得分析，不证明可泛化；Skill 需要适用条件、权限边界、失败出口与维护责任。暂不自动创建或改写 Skill。

## 10. 保持简单与评估标准

现在不做：通用图谱、向量库迁移、全局自动学习、统一可信度分数、全记录 TTL、后台全会话扫描、自动 Skill 生成、专门冲突中心与目录迁移系统。

先评估：重复调查是否减少，过时/越界召回是否减少，关键结论是否可追溯，当前任务能否恢复，未知是否如实保留，上下文与审核成本是否可控。
不以记忆条数、自动化比例或所有测试变绿替代实际使用质量。
