## 1. 目标和证据边界

先用完全虚构、可审计的材料回答：哪些必要事实能恢复？哪些不应成立的事实被错误提升？
不得把 242/242 的既有离线软件回归、文本 grounding 或人工批准当作科研质量证据。

分三层报告，不能互相替代：

| 层 | 输入与被测对象 | 能证明什么 / 不能证明什么 |
|---|---|---|
| A：确定性契约 | 固定证据、固定合法/非法模型响应、实际提炼/存储/上下文路径 | 校验、隔离、状态保留和检索行为；不能衡量模型选择质量 |
| B：合成语义质量 | 同一合成材料，独立金标，对实际候选、发布内容及召回上下文逐项审阅 | 在这些场景中的信息保真与召回；固定 provider 不代表真实模型 |
| C：真实模型/任务 | 经另行授权的小样本、人工证据核验与独立报告 | 仅对已评样本及配置有效，不能从 A/B 外推 |

本方案的离线实现不调用任何模型或科学软件。B 的对象是系统保留的信息，不是假定已有回答模型。
若以后评估回答生成，须把回答模型、配置、输入与错误另列，不能混进召回分数。
所有体系、软件版本标签、路径、错误和数值都是合成字符串，不声明真实软件支持或科学有效性。

## 2. 夹具与金标

独立 `eval/` 目录区别于功能单测；当前含纯内存提炼和直接 API 存储/召回集成子集，不含真实 Pi 宿主质量评测。
夹具与判分规则须在运行前冻结并标版本、内容摘要，禁止看结果后悄悄改金标。
每个场景由四部分组成：

1. **来源流**：用户计划、工具观察、助手声明；保留顺序、角色、完整否定语句、回合和会话身份。
2. **初始状态和操作**：显式实体/修订关系、候选决定、查询、当前实体、预算、会话切换顺序。
3. **金标**：原子事实、来源定位、必需限定词、禁止断言、不应召回的记录身份、允许缺失项。
4. **固定响应**：合法保守响应、合法但语义不当响应、非法 grounding/schema 响应；分别运行，不能只测理想响应。

每个原子事实至少含 `factId`、`sourceRef`、`subject`、`predicate`、`object`、
`scope`、`qualifiers`、`critical`；这些是评测清单字段，不是新增生产接口。
`scope` 区分体系/方法/运行/修订；`qualifiers` 保留计划、否定、假设、单位、未验证等限制。
禁止断言独立编号，记录触犯的层次（候选/知识/上下文），避免长文掩盖局部错误。

示例金标（不是输入 schema）：

- F01：run-A 只是准备好输入；执行、终止、收敛、有效性不可由此推出。
- F02：run-B 的最后 SCF 迭代能量为 -10.25 Ha；同时保留“未收敛、错误终止”，不可称为有效总能量。
- X01：禁止“run-A 已完成”；X02：禁止把 F02 的值归到 run-C，或丢掉单位与失败限制。

数值只在合成证据中人工给定；自动提炼仍不得产生结构化 result。
显式科学记录和自动抽取式文本路径分开设样本，不能用前者冒充后者支持自动数值 grounding。

## 3. 最小场景矩阵

每行至少包含正例和一个最小差异反例；身份与证据均独立，标题可以故意完全相同。

| ID | 场景与操作 | 必须恢复 | 禁止 / 隔离要求 |
|---|---|---|---|
| P1 | 用户计划计算；助手建议参数；尚无执行观察 | 计划、建议身份、未执行及待办 | 不生成已执行结果、用户承诺或已采纳决定 |
| P2 | 助手声称成功；工具只返回输入已写入 | 声明来源与实际观察范围 | 不以助手陈述或工具 completed 推断科学成功 |
| F1 | 失败 run-B；提出恢复参数 old→new；尚未重跑 | 精确错误、失败阶段、最后迭代能量及限制、假设、旧新值、待验证 | 不把建议称为已修复；不把最后迭代值称为有效总能量 |
| F2 | 新 run-C 报告正常终止/收敛；科学有效性仍 unchecked | run-B 失败与 run-C 成功观察并存、各自证据 | 不回写 run-B 成功；不从收敛推断科学有效 |
| E1 | 同体系、同标题、method-A 与 method-B；只激活 A | A 的设置、适用范围、关联运行 | 不混入 B 的能量、基组、色散或设置 |
| E2 | 同名 system-A/system-B；方法修订 r1→r2 为显式关系 | 活动体系及 current 修订 r2 | 不按标题合并、不召回 r1；同名但无替代关系的记录保留独立身份 |
| R1 | 同体系/方法、多运行路径；两个运行均 current | 每个 run 的位置、执行/终止/收敛/有效性及未知字段 | 不以最新时间或相同标题合并运行；未知不填零或成功 |
| Q1 | review pending、rejected、approved+publication pending 混合 | 已发布 current 知识可查；决定/发布阶段可区分 | 三种未发布状态均不入知识命中或知识上下文 |
| Q2 | 完成发布；另有 superseded/archived 与相同来源片段 | published current；reported/unresolved 的待核实标记 | 批准/auto 不升级验证；旧修订和归档不复活 |
| C1 | 计算任务切新会话后仅问“继续” | 体系、方法、运行位置、阻塞、下一步、未验证限制 | 不丢掉失败状态、不杜撰运行或提交动作 |
| C2 | 软件任务切会话后“继续”；有通过、失败、跳过、未运行检查 | 模块、改动位置、实际检查范围、未解决项及下一步 | 不把跳过/语法通过当完整验证或科研正确 |
| I1 | 无标记、不同项目使用同标题；合成敏感哨兵 | 无标记禁用、项目边界、安全原因码 | 不回传另一项目的身份/文本或已过滤哨兵；不以真实秘密作夹具 |
| B1 | 重复来源、互补长片段、预算收紧及证据截断 | 去重后仍保留互补信息；截断可见 | 不把相同标题/前缀当完整重复；截断不能支持缺失的事实 |

Q1 必须按**通道和记录身份**判分：知识检索与 knowledge 上下文禁止未发布候选。
state/journal 可能合法保留同一原始工作片段，但必须标为工作观察/待核实，而非已批准知识。
禁止只用字符串在整个上下文出现与否来判断 pending 泄漏；同时禁止借工作通道升级候选事实。

E1/R1 还须分别运行显式实体查询、带活动实体的默认上下文、无活动实体的普通查询。
无实体提示时允许返回多个有明确身份的 current 记录，不能把“返回多个”误判为串线。
含糊查询不得期待系统凭同名标题猜中唯一运行。

## 4. 执行与对照协议（部分实现）

1. 先冻结夹具和金标；逐场景记录生产配置、输入及响应摘要，不读取用户数据。
2. 后续 runner 仅使用新建、可清理的临时沙箱；初始化标记如确有需要仅限沙箱，不能在仓库创建 `.pi-root`。
   用户已明确授权仅在全新、可清理的临时沙箱内创建标记；该权限不扩展到仓库或真实项目。
3. 同一来源流分别走当前默认 v1 和显式 v2；各用独立沙箱，不共用包、不自动迁移、不同时加载两扩展。
4. 保持来源、查询、输入顺序、固定响应和可比的上下文预算一致；记录各自配置及能力差异。
   v1 不支持的入口注明 unsupported；共同任务仍按可观察结果评分，不伪造 v1 的实体/审核接口。
5. 分别取候选、已发布知识、显式检索、默认上下文快照。知识与工作通道分别归属，比较生成前后的原子事实。
6. 同一场景至少原序、干扰记录前置、干扰记录后置三个固定变体；重复运行不能复用旧输出。
   重复次数和超时由 runner 显式设置；超时/异常算执行失败，不以跳过改善分母。
7. 自动校验身份、阶段、精确引用、字段与长度；语义项由人工核对主语、谓词和限定词。
   合法引文但错误标题/分类也要计错，不能以 schema 通过免除语义错误。
8. 对每个失败保留最小来源/输出定位和错误归因；发现无法正确计分时标为 unresolved，而不是判通过。

不使用远程 LLM 作裁判，不把固定 provider 的候选选择称为真实抽取能力。
比较工具建议复用既有领域和存储接口；具体导出函数、签名和测试复用点须在实现前定点核验。

## 5. 指标和门槛

| 指标 | 定义与报告方式 |
|---|---|
| 必需事实覆盖 | 正确恢复且保留全部必需限定的事实数 / 场景必需事实数；缺失与错误分列 |
| 禁止性错误 | 按唯一禁止断言 ID 计数，同时保留发生次数和层次；每项给来源/输出定位 |
| 下一步定位正确率 | 正确恢复操作、目标身份、位置及前提的续接案例数 / 适用续接案例数 |
| 实体/生命周期污染 | 不适用实体或未发布/旧修订进入禁止通道的记录数；不得只算比例掩盖单次泄漏 |
| 不确定性保留 | 应保留来源、失败、假设、未核实标签的事实中完整保留的比例 |
| 上下文开销 | 注入长度，按 UTF-16 code units 计；另报 UTF-8 字节数及配置预算、截断情况 |
| 延迟 | 每场景端到端及各阶段耗时 ms；报告样本数、中位数和最大值，不作无样本性能结论 |
| 模型 usage | 只报实际返回的 inputTokens/outputTokens；缺失为 unknown，固定无调用路径为 not-applicable |

所有比例同时展示分子/分母；无适用项为 not-applicable，不算 100%。
正确恢复要求事实和限定能在同一可归属单元中关联；散落关键词、只出现数值或命中标题均不足。
语义审阅记录评审者与理由；有争议项保持 unresolved，并另列乐观/保守边界，不抹平争议。

合成验收门槛：每个固定场景及变体的关键事实覆盖 100%，禁止性错误和污染为 0，
续接下一步定位 100%，关键不确定性完整保留；任何执行失败或 unresolved 均不能宣布通过。
非关键事实覆盖仍逐项报告，不用总体均分掩盖关键失败。
这些是**拟定门槛，不是已取得结果，也不单独构成发布许可**。
