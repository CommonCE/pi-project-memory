## 4. 推荐发布流程

默认建议保留旧 repo 私有，在新的私有 repo 验收后再公开：

1. 完成清理，并在原工作区保留已有修改和旧历史。
2. 使用显式文件白名单导出到新的空目录；不复制 .git、真实记忆、凭据、本地配置或生成结果。
3. 审查导出内容、归属/许可证和计划使用的提交身份。
4. 经明确授权后初始化新仓库并创建初始提交，核对只有预期历史和文件。
5. 经明确授权后推送新的私有 GitHub repo；检查远端内容、分支/标签、设置和发布附件。
6. 经明确授权后将新 repo 转公开。旧 repo 不自动删除或改可见性。

不要直接对旧仓库执行 git archive 后无审查发布：它仍可能包含当前文件里的本地内容。
不把“强推一个新 main”当作旧对象清除证明，也不强推 --mirror 作为本阶段动作。
如果必须沿用旧 repo，需要另做所有引用/缓存的清理计划。
真正的凭据泄露先撤销/轮换；删除历史不能替代这一操作。
