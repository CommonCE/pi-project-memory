# v2 机制规格与阶段契约

状态：M1–M3 已实现，M4 冻结在离线契约，M5/M6 已完成本地契约验收，M7 部分完成。本文保留机制设计与阶段记录，不再作为总体架构或开发顺序的唯一入口。当前目标与差距见 [总体架构](architecture.md)，优先级见 [路线图](roadmap-v2.md)，具体已实现行为按对应阶段契约和测试证据核对。
用户已确认项目内默认存储、不兼容旧记忆。历史建议不因保留在本文就成为已实现接口；本轮架构整理不改变 schema 或现有契约。
默认安装入口仍为旧 index.ts；新版宿主入口 v2.ts 必须显式加载，不能与旧入口同时启用。旧操作明确拒绝新版配置。

## 1. 目标与非目标

目标：
- 新会话能恢复体系/代码项目、当前任务、最近运行、结果位置、阻塞点与约定下一步。
- 保留丰富任务的有用细节，同时区分事实、假设、计划和助手陈述。
- 普通开发任务不承担无关的量化计算字段。
- 本地可读 Markdown 为权威记录；索引可重建，无服务端依赖。

非目标：
- 兼容/迁移旧 pack、跨项目自动检索、全局知识库、自动运行计算。
- 在初始化时扫描计算文件或后台调用模型。
- 把保存条数当质量指标，或宣称引用校验能验证科学结论。
- 自动清理旧数据、科学输出或旧 Git 历史。

## 2. 项目边界与位置

默认根为用户显式初始化的目录；已有祖先标记时沿用最近根，不默默建立嵌套项目。
嵌套项目需显式选择独立初始化（命令形式在 M1 定稿）。
普通启动不创建标记，无标记不读写记忆；每次持久化重查作用域。
子目录启动仍读取根的 .pi-memory，不在子目录另建库。

配置位于 .pi/project-memory.json，保存 schemaVersion、稳定 UUID、显示名称和相对 memoryPath。
默认 memoryPath 为 .pi-memory；新格式不读取旧注册表，也不导入旧 pack。
若初始化发现既有旧配置或未知非空目标，明确拒绝并说明冲突，不覆盖、不猜测格式。
项目复制保留 UUID 时仍各自读写本地路径，不发生中央绑定或隐式共享。
第一阶段不支持项目外路径或后代符号链接，不跟随路径逃逸；根目录使用真实路径确定边界。

```text
<project-root>/
  .pi-root
  .pi/project-memory.json
  .pi-memory/
    overview.md
    state.md
    knowledge/
      systems/
      methods/
      runs/
      results/
      diagnostics/
      software/
      workflows/
      decisions/
    journal/
    .internal/
      records/       # 不可变规范记录与修订，权威存储
      reviews/
      diagnostics/
      index/         # 可删除重建的索引
```

knowledge 从 .internal/records 的知识修订生成；overview、state、journal 从 .internal/work 的不可变工作事件生成。它们都是派生 Markdown 视图，不是另一套独立事实库。
普通手动修改视图不得静默吞掉：检测修改并报冲突，通过显式导入/修订采纳。
初始化提示忽略 .pi-memory；只有明确授权后才追加项目 .gitignore，不重写已有规则。
发布导出始终使用文件白名单排除记忆，即便用户忘记 Git ignore。

## 3. 三层记忆与两条写入轨道

### 3.1 有界工作记录 journal

自动轨道保存本轮有价值的目标、执行观察、未解决项、修改定位和测试情况。
不要求它先成为长期结论；失败任务也可以留下失败记录。
不保存原始聊天、thinking、图片、全部工具参数或完整日志；无可用信号则不生成记录。
助手总结以 assistant_claim 标记，不能作为工具观察或科学事实。
临时尝试不能自动进入“已约定下一步”；必须有用户承诺或明确接受的计划依据。

### 3.2 当前视图 overview / state

overview：项目目的、已采用体系/方法或软件架构、重要约定、关键源文件与结果入口。
state：活动任务、最近可定位运行/工作项、阻塞、待核实项、下一步。
默认加载仍需遵守预算和验证标记；不确定项放独立区域，不伪装成确认事实。
压缩前快照可帮助恢复工作状态，但不能据此提升知识验证等级。

### 3.3 长期 knowledge

建议默认自动积累 journal 和可追溯状态；长期知识默认 review，可按项目显式开启 auto。
一次已完成任务允许提炼互补条目，不按每个标量拆笔记，不要求填满数量。
review 决定是否采纳；verification 表达证据性质，二者独立。
自动模式只影响是否发布，不能提升 verification 或 run validity。
关闭全部学习时，不调用学习模型，也不自动记录 journal/state；显式保存仍需用户请求。

## 4. 领域模型（建议契约）

公共字段：
- schemaVersion、id、revision、projectId、kind、title、content、created、sourceTurn。
- entities：类型化引用，例如 system、method、run、component、task；引用由已存在记录或显式创建建立。
- provenance：用户确认、工具观察、助手陈述、模型提炼的来源类型。
- verification：reported / evidence-backed / user-confirmed / unresolved；表示出处与检查范围，不保证科学正确。
- lifecycle：current / superseded / archived，和审核 pending / approved / rejected 分离。
- evidence：已建立的项目相对文件定位或有界回合片段引用。引用不触发读文件或执行命令。
- relations：显式相关实体和 replacesRevision；不得凭标题相似猜测替代。
- 未提供字段为 unknown/缺省，不用 0、false 或“已成功”填空。

领域分类：
| kind | 范围 |
|---|---|
| systems | 结构来源、组成、编号、周期性、电荷、自旋/磁态；仅记录已知值 |
| methods | 方法/泛函、基组/赝势、色散及关键设置组合、理由、适用范围 |
| runs | run id、输入/输出位置、软件及版本、执行身份与状态 |
| results | 物性、值、单位、能量等定义、来源运行、收敛与有效性限制 |
| diagnostics | 原始错误定位、诊断是假设还是确认、参数旧新值、验证情况 |
| software | 模块/接口、环境、构建与测试、兼容约束、已知限制 |
| workflows | 触发条件、前提、步骤、资源和副作用、验证边界 |
| decisions | 用户采纳的选择、依据、后果、替代关系 |

runs 至少分离：
- execution：unknown / prepared / submitted / running / terminated；
- termination：unknown / normal / error / cancelled；
- convergence：unknown / converged / not-converged / not-applicable；
- validity：unchecked / accepted-with-scope / rejected。

它们不是单一线性状态机；提交成功不能推出开始运行，正常终止不能推出科学有效。
结果中的数字只从可定位证据提取；不能由模型生成数字或推断缺失单位。
软件检查也区分未运行、通过、失败、跳过及实际检查范围。

## 5. 写入、修订与恢复

- records 先独占原子发布完整修订；保留现有 exclusive 的完整可见性保障。
- 采用项目级写锁和 expectedRevision 比较；并发更新冲突明确返回，不覆盖较新状态。
- 发布后生成可重建视图；视图损坏/中断可从记录恢复，不把半次更新当成完整事务。
- 新的状态视图采用同目录临时文件完整写入后原子替换，仅限插件拥有且通过冲突检查的派生视图。
- 更新同一实体需明确 id 和前一 revision；保留所有历史，不同体系/运行不按同名合并。
- journal 使用 projectId + session + turn + payload 身份实现重试幂等。
- 崩溃锁不自动抢占；有诊断及显式恢复路径。保留磁盘空间上限，达到时暂停并提示，不自动删除数据。
- 初期建议 journal 上限 50 MiB、诊断 5 MiB，后续做显式归档；具体扫描及记录上限在 M1 固化并测试。
- 不能写出 .pi-memory，不改写输入/输出、checkpoint、波函数、cube 或任何计算结果。

## 6. 学习输入与执行

先形成结构化 evidence envelope，再调用一次有超时的当前宿主模型；不引入额外 SDK。
输入包含本轮用户约束、工具观察、现有 state 和必要相关实体背景；历史工作记录只是背景，不能变成本轮新证据。
保留失败工具的安全证据；主回合取消/模型失败时，不采纳残缺模型归纳，但允许独立发布已完整收集的本地工作观察。
敏感过滤在截断和模型发送前执行；过滤失败可丢弃片段并记录原因码，不保存被过滤原文。
默认不扫描未读取文件；文件定位存在不等于文件内容已核验。
会话切换、标记变化、配置关闭后取消请求并在写入前再次校验。
不启动脱离生命周期的后台学习，不盲目重试有副作用的写入。

建议初始上限：学习输入 48000 字符，工具单项 8000，输出 6000 tokens，超时 60 秒；
这些是预算，不是候选配额；需记录截断和实际使用量。
保留自定义更小预算及 learning off；扩大预算不能替代结构化证据。

## 7. 召回与默认上下文

自动上下文总预算建议 12000 字符：
- overview 最多 2500；
- state 最多 3500，内部独立标注待核实区域；
- 剩余预算用于相关知识和近期工作片段，含标题、来源和元数据开销。

没有关键词的“继续上次任务”仍加载概览和状态。
相关检索组合当前输入、state 活动实体、有限近期任务标签和 BM25；
不把全部历史堆入查询，不跨项目搜索。
工作上下文发现显式活动 run 时，额外进行一次限 8 项的 run 优先搜索，与宽检索合并去重后仍最多纳入 4 项；
明确归属其他 run 的知识不因共享体系/方法而混入。run 记录以自身 id、数值结果以 result.runId 为准，其余记录按显式 run 引用判断。
共享背景可保留；显式选多个 run 或没有选 run 时不强行缩成单一运行。此规则只影响知识上下文，显式 search API 仍宽检索，不重写来源、工作历史或科学状态。
缺失/错误 run 关联不能靠关键词、同名体系或这层筛选自动修复；跨 run 诊断只要显式包含活动 run 仍可入选。
长期知识默认排除 pending、superseded、archived；reported/unresolved 内容只能以明确待核实身份出现。
journal 相关片段也是工作记录，不作为已验证知识。
按实体和来源去重，避免 overview/state/knowledge 重复占满预算。
索引只读当前项目安全清单，有限文件数、字节数、深度；截断必须可见。
第一阶段无 embedding；未来是否引入以评测缺口决定。

## 8. 接口与可观测性

保留用户熟悉的 /memory-init、/memory status、/memory search、/memory review 和两个模型工具名称。
新 schema/工具参数允许破坏兼容，但正式改动必须更新工具契约和测试。
新增状态检查/修订的接口在 M2 定稿；搜索工具只读，写入工具不具备提交、运行、取消计算或删除能力。

诊断使用安全原因码：
disabled、no-marker、no-signal、evidence-truncated、sensitive-fragment-dropped、
model-timeout、model-error、invalid-json、invalid-grounding、invalid-schema、
review-pending、revision-conflict、duplicate、inventory-bounded。
统计 attempted/accepted/queued/published 与各原因数量；默认不保存原始 prompt、回复、路径值或 provider 错误。
显式本地诊断也不复制敏感片段。阶段失败不影响主任务结果。
费用单独报告模型 usage，不能声称自动并入宿主总额。

## 9. 实施顺序与验收门槛

### M1：新存储与领域模型（已实现独立 CLI/API）
只实现 root/config/record/revision/投影视图/显式保存查询；旧格式冲突明确拒绝。
入口为 `pi-project-memory v2`；M1 本身不接自动事件。目录增加 `.store.json` 身份清单；overview/state/journal 的内容生成由后续 M2 提供。
M1 使用类型化 entities 和修订链；更广的 relations、task 实体、自动审核/归纳诊断在后续阶段定稿。
验收：子目录/嵌套/撤销标记、移动路径、配置冲突、符号链接、并发、崩溃、幂等、旧数据字节不变。
不创建新 Git 历史，不运行计算。

### M2：journal + state + 默认底座（已实现独立 v2.ts 扩展）
用确定性、有界工作片段投影 state，提供显式 overview/状态更新，并接入宿主生命周期与压缩；M2 不调用学习模型。
工作学习默认为 on，项目/会话可 off；显式保存不受学习 off 限制。上下文总预算 12000 字符，状态摘要优先 5500、概览 2500，其余相关知识。
工具 observations 只表示运行观察，assistant claims 不升级为科学结论；失败/取消不采纳残缺助手陈述，但可保留完整工具结果。
规范工作事件位于 .internal/work，和 M1 共用写锁；独立上限 10000 项/50 MiB，单事件 100000 字节。
验收：换 session 后“继续”能恢复任务/阻塞/位置；失败计算不丢失、不变成功；模型失败仍保留可独立确定的观察。
验证预算、手动修改冲突、取消、作用域变化、off 和隐私保护。

### M3：长期提炼与实体检索（已实现，质量评测留给 M4）
模型结构化提炼、review/auto 分离、明确修订、实体/BM25 排序与安全诊断。
验收：计划不变结果、人工批准不升级验证、不同方法/运行不混淆、pending 不进入知识召回。

第一阶段为独立 CLI/API：显式 propose、候选列表、approve/reject、显式修订目标和 CLI 实体过滤，见 [M3 契约](m3-usage.md)。候选不进入知识清单；审核不升级 verification。批准决定先持久化，再以同一 requestId 恢复知识发布；共用 M1 写锁和视图保护。

第二阶段提供 src/v2-extraction.mjs：过滤先于截断的当前回合证据 envelope、严格引文选择、确定性候选生成，以及可注入模型适配器的超时/取消/作用域守卫。只建立文本 grounding，不自动提炼自由科学摘要，不接受结构化数值候选；整个保留来源片段以未验证身份入队。离线桩验证不代表宿主模型质量。

完成阶段已接宿主当前模型和 agent_before_settle：默认 review，每用户范围最多一次有界调用；显式 auto 只改变发布策略，不提高验证或运行有效性。Pi 提供 review/curate/extract，项目支持 longTermMode 和有上限的 extraction 配置。作用域撤销会 abort，配置/off 在共享锁内及规范记录/投影发布前重查；错误、截断和迟到回复不采纳。自动上下文按活动实体优先，来源与完整内容去重；安全诊断及可用 usage 仅独立聚合报告。

M3 采用保守的抽取式提炼，不开放模型自由生成科学正文或结构化数值。文本 grounding 不保证语义/科学有效性，标题/分类仍须审核；不以功能测试代替质量评测。合成与真实任务质量、跨场景覆盖及文档去本地化继续按 M4 验收。

### M4：计算化学记忆生成、续接质量与文档去本地化
主目标与分层验收见 [M4 开发目标](m4-chemistry-goal.md)。优先建立来源→实际提炼 API→审核→存储→新进程召回的纵向样例，再定位生产瓶颈。
固定响应保真、真实模型自动选择、实际 Pi 会话续接及人工科学审阅分别报告；矩阵变绿不代表实际生成质量已改善。
先合成夹具，再经单独授权进行真实模型小样本；不得暗中使用真实科学计算作为测试。
至少覆盖：
1. 计算续接：体系/方法/运行位置/待办均能找回。
2. 失败诊断：错误证据、假设、旧新参数和未验证项不混淆。
3. 软件续接：模块、改动、实际测试、未解决项可恢复。
4. 方法替代/同名多体系：只取适用实体和当前修订。
5. 负例：无证据数值、收敛、成功和用户承诺均不出现。
6. 隔离/隐私：无标记、跨项目、敏感文本均不泄漏。

用相同夹具比较当前版/新版：必需事实覆盖、错误事实数、下一步定位正确率、注入长度、延迟、模型 usage。
发布门槛：固定夹具关键事实全部恢复，禁止性错误为零；这不证明真实模型归纳质量，真实效果另行记录。
笔记数量仅作诊断，不设条数增长目标。

M5 文件夹作用域（[设计](m5-folder-scope.md)、[ADR 0006](../decisions/0006-folder-scoped-memory.md)）与 M6 计算化学卡片已完成本地契约验收；M7 已收缩为最小续接闭环，当前仅共享简报与 CLI 完成，详见 [M7 计划](m7-plan.md)。不再按旧“整理 UX”范围扩建。原 M5 发布阶段顺延为 M8；后续治理按路线图 P2 等独立切片安排。

### M8：干净仓库发布（原 M5）
遵循 publication-audit.md，单独授权 Git/远端操作。当前路线将使用验收安排为独立步骤，M8 保留质量与发布门槛；真实模型、真实 Pi 会话及真实项目试用分别取得相应授权，不要求全部未来治理功能完成才讨论发布。
