## 2. 目标（来自路线图，不是字段名契约）

| 卡片类别 | 应保留的信息 |
|---|---|
| systems | 组成、结构来源、电荷、自旋/多重度、周期性 |
| methods | 方法/泛函、基组/赝势、色散、溶剂、软件及版本、适用边界 |
| runs | 输入/输出位置、运行身份、execution/termination/convergence/validity 四轴 |
| results | 值、单位、定义、来源运行、收敛及有效性限制 |
| diagnostics | 原始错误、阶段、假设与确认的区别、旧/新参数、是否重跑 |

目标是可校验、可读、有来源和限制，不只是把自由文本换成漂亮 Markdown。
software/workflows/decisions 仍属既有 kind；是否需要额外模板必须先说明收益，不能顺手扩大范围。

## 3. 编码前必须解决的契约问题

1. **旧数据兼容**：卡片是否为可选附加结构？已有自由文本、旧 runs/results 如何继续读取、修订和检索？哪些新操作触发严格校验？禁止静默迁移或重写历史。
2. **unknown 与拒绝发布**：区分“可显式记录未知”与“条件必填缺失不能发布”。不把缺失填成 0、空字符串、默认单位、已收敛或已验证；不能为了卡片完整而伪造字段。
3. **体系身份**：明确 charge/spin/multiplicity 的含义和适用条件；不把总自旋、非配对电子数和多重度当同一量，不把分子条件强加给所有周期体系。
4. **运行与来源**：result 指向哪个 run、哪个修订或输出证据？运行后续修订如何影响既有结果的限制？正常结束、SCF/几何收敛和科学有效性不能互相代替。
5. **冲突身份**：同 run 同性质的“同一性质”由哪些字段确定（定义、单位、体系、方法、分量等）？仅标题或属性名相同不足以自动合并；不做无依据的单位转换。
6. **显式替代**：复用现有修订/lifecycle/引用机制还是新增表达？必须先确认实际实现和账本保护，不猜接口；并发下的冲突也不能绕过。
7. **发布边界**：直接 save/revise、候选 staging、人工 approve、auto approve 各在哪里校验？未知字段和模型生成内容不能借审核升级为科学事实。
8. **渲染边界**：卡片页、知识视图、目录页、搜索摘录和简报分别展示多少信息？所有派生视图不参与 grounding，保留现有预算和手改冲突保护。

涉及科学含义的疑问先用适用领域 skill 和版本证据核对；本轮没有授权检查真实输入、诊断真实计算或执行计算。

```bash

node --test test/v2-scope*.test.mjs test/v2-folder-views.test.mjs
# 再运行 M6 新增的定向测试，文件名由已确认设计决定
PI_TEST_HOST_PACKAGE="${PI_TEST_HOST_PACKAGE:?Set PI_TEST_HOST_PACKAGE to the host package.json}" timeout 300s npm test
```

- 允许只读检查、代码/文档修改、隔离临时目录内创建和清理、本地单测；测试不得触达真实用户设置或记忆包。

- 禁止远程/付费模型、计算、作业提交；真实模型、真实项目续接和人工科学审阅属于另外的验证层，需另行授权。
- 不重做 M4 矩阵，不提前做 M7 自动迁移/跨根整理或 M8 发布；路线图中个别已在 M5 落地的 UX 不重复实现。
